# VS Code + Claude Skill

---

## 1. Установка Claude Code в VS Code

### Через Marketplace
1. Открой VS Code
2. `Ctrl+Shift+X` → поиск **"Claude Code"**
3. Установи расширение от Anthropic
4. При первом запуске авторизуйся через браузер

### Через CLI (Claude Code Terminal)
```bash
npm install -g @anthropic-ai/claude-code
claude   # запуск в текущей директории проекта
```

> **Совет**: Запускай `claude` всегда из корня проекта — так Claude видит всю структуру.

---

## 2. Основные режимы работы

### Inline Chat (в редакторе)
- Выдели код → `Ctrl+Shift+I` (или `Cmd+Shift+I` на Mac)
- Появится чат прямо в редакторе рядом с выделением
- Claude видит выделенный фрагмент как контекст

### Панель чата
- `Ctrl+Shift+P` → "Claude: Open Chat"
- Полноценный чат с доступом ко всему проекту

### Терминал (Claude Code CLI)
```bash
claude "добавь логирование в функцию processOrder"
claude --continue   # продолжить предыдущий диалог
claude --resume     # выбрать прошлую сессию
```

## 3. Slash-команды в редакторе

| Команда | Что делает |
|---|---|
| `/fix` | Исправить ошибку (выдели код с ошибкой) |
| `/doc` | Добавить документацию/комментарии |
| `/test` | Сгенерировать unit-тесты |
| `/explain` | Объяснить как работает код |
| `/improve` | Рефакторинг и улучшение |
| `/commit` | Написать сообщение для git commit |

## 4. Файл CLAUDE.md — контекст проекта

Создай файл `CLAUDE.md` в корне проекта. Claude читает его автоматически при каждом запуске.

### Что писать в CLAUDE.md:
```markdown
# Проект: MyGame

## Стек
- Unity 2023.2, C#, URP
- Архитектура: MVC + ScriptableObject-driven data
- Тесты: Unity Test Framework (NUnit)

## Соглашения по коду
- Приватные поля: _camelCase с подчёркиванием
- Публичные свойства: PascalCase
- Используем [SerializeField] вместо public
- Async методы заканчиваются на Async

## Структура папок
- Scripts/Core — менеджеры и системы
- Scripts/Player — всё связанное с игроком
- Scripts/UI — только UI логика

## Что не трогать
- Папка Plugins/ — сторонние библиотеки, не изменять
- LegacyAnimator.cs — устаревший код, будет удалён

## Частые задачи
- Новый враг: наследуй от EnemyBase, добавь данные в ScriptableObject
- Новый UI экран: создай UXML + USS, добавь контроллер в Scripts/UI
```

## 5. Файл .claudeignore

Исключи из контекста ненужные файлы (аналог `.gitignore`):
```
# .claudeignore
node_modules/
.git/
*.log
Build/
Library/          # Unity cache
Temp/             # Unity temp
*.meta            # Unity meta файлы (опционально)
Packages/         # UPM пакеты
```

## 6. Как писать хорошие промпты

### Плохо → Хорошо

| ❌ Плохой промпт | ✅ Хороший промпт |
|---|---|
| "Почини это" | "В методе `SpawnEnemy` при `count > 10` выбрасывается NullReferenceException. Вот стектрейс: [...]" |
| "Добавь фичу" | "Добавь в класс `PlayerInventory` метод `SwapItems(int slotA, int slotB)`, используя существующий список `_items`" |
| "Напиши тесты" | "Напиши NUnit тесты для `HealthComponent.TakeDamage()`: проверь что HP не уходит ниже 0, что событие `OnDied` срабатывает при смерти" |
| "Объясни код" | "Объясни что делает этот метод и почему используется `FixedUpdate` вместо `Update`" |

### Шаблон хорошего промпта
```
[ЧТО НУЖНО СДЕЛАТЬ]
[КОНТЕКСТ: какой класс/файл/метод]
[ОГРАНИЧЕНИЯ: паттерны, стиль, зависимости]
[ЧТО УЖЕ ПРОБОВАЛ / В ЧЁМ ПРОБЛЕМА]
```

**Пример:**
```
Добавь систему охлаждения (cooldown) в WeaponController.cs.
Класс уже имеет метод Shoot() и поле fireRate.
Используй корутину, не создавай новых зависимостей.
Cooldown должен показываться через уже существующее событие OnCooldownChanged(float progress).
```

## 7. Работа с большим кодом

### Дай Claude нужный контекст
```bash
# В CLI — указывай файлы явно
claude "отрефакторь этот класс" --files Scripts/Player/PlayerController.cs

# Или через @ в чате
@Scripts/Player/PlayerController.cs отрефакторь метод HandleInput
```

### Декомпозируй задачу
Вместо "переделай всю архитектуру":
1. "Выдели интерфейс IDamageable из класса EnemyHealth"
2. "Замени прямые ссылки на GameManager на event-based систему в PlayerController"
3. "Переведи класс SaveSystem на async/await"

## 8. Workflow для разных задач

### Отладка ошибки
```
1. Скопируй стектрейс из Unity Console
2. Выдели проблемный метод в редакторе
3. Ctrl+Shift+I → /fix → вставь стектрейс в сообщение
```

### Code Review
```
Проверь этот код на:
- Утечки памяти и подписки на события без отписки
- Потенциальные NullReferenceException
- Нарушения принципа единственной ответственности
- Возможные проблемы с производительностью в Update()
```

### Документация
```
Выдели класс → /doc
Claude добавит XML-документацию ко всем публичным членам
```

### Генерация тестов
```
Напиши NUnit тесты для [ClassName].
Покрой happy path и edge cases.
Используй Unity Test Framework. Мокай внешние зависимости через интерфейсы.
```

## 10. Советы для Unity-проектов

- **Не отправляй .meta файлы** в промпт — они шум
- **Указывай версию Unity** в CLAUDE.md — поведение API отличается
- **Давай ссылки на документацию** если используешь новые API: "используй новый Input System (com.unity.inputsystem 1.7+)"
- **Проси объяснения** если не понимаешь сгенерированный код: `/explain` или "объясни почему ты выбрал этот подход"
- **Итерируй**: "это хорошо, но теперь добавь обработку случая когда список пустой"
- **Проси альтернативы**: "покажи 2 разных способа реализовать это"
